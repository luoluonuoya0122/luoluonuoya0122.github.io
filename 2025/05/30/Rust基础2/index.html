Option

在 Rust 中，Option<T> 是一个常见的枚举类型，用来处理可能存在或者不存在的值。它是 Rust 语言用于避免空值（null）问题的核心工具。Option<T> 有两个变体：

  • Some(T)：包含某个值。
  • None：表示没有值。

以下是一些常见的使用场景：

1. 处理可能为空的值

在许多编程语言中，null 被用来表示值不存在。Rust 通过 Option 避免了空指针问题，显式地定义了值是否存在。

2. 安全地处理函数的返回值

当函数可能失败时，返回 Option 让调用者清楚知道如何处理成功或失败的情况。

3. 链式操作

可以通过 map、and_then 等组合操作链式处理 Option 值，简化代码。

4. 与集合交互

Option 也可以与迭代器、集合一起使用，例如查找操作。

5. 解构匹配

Rust 提供模式匹配，通过 match 语句解构 Option，让代码在处理不同分支时更加明确和清晰。

6. 简化错误处理

Option 可以用 unwrap_or, unwrap_or_else 或 unwrap_or_default 等方法简化错误处理。

总的来说，Option 用于明确表达可能存在或不存在的值，帮助避免错误空值引用，并且通过匹配和链式方法提供了非常强大的错误处理能力。

结构体

定义结构体

  • 使用struct关键字胃整个结构体提供一个名字
  • 结构体的定义的位置没有要求，实例化的作用域在定义的范围内即可
  • 大括号中，定义每一部分数据的名字和类型，成为字段（field）
  • 使用逗号分隔每个字段

创建结构体实例

  • 初始化实例时，每个字段都需要进行初始化
  • 初始化时的字段顺序不需要和结构体定义时的顺序一致
  • 使用逗号分隔每个字段

特殊的结构体

  • 元组结构体
  • 单元结构体

元组结构体

结构体必须要有名称，但是结构体的字段可以没有名称，这种结构体长得很像元组，因此被称为元组结构体。
元组结构体在你希望有一个整体名称，但是又不关心里面字段的名称时将非常有用。
例如Point 元组结构体，众所周知 3D 点是 (x, y, z) 形式的坐标点，因此我们无需再为内部的字段逐一命名为：x, y, z。

单元结构体

如果你定义一个类型，但是不关心该类型的内容，只关心它的行为时，就可以使用单元结构体

  • 定义AlwaysEqual，我们使用struct关键字，接着是我们想要的名称，然后是一个分号
  • 实例化不需要花括号或者圆括号

定义方法Method

  • 使用fn关键字和名称声明，可以拥有参数和返回值，同时包含再某处调用该方法时会执行的代码。
  • 方法和函数时不同的，因为它们在结构体的上下文中被定义，并且他们第一个参数总是self，它代表调用该方法的结构体实例

模式匹配

  • 什么是模式匹配：模式匹配是一种强大的功能，可以检查数据的结构并进行相应的操作
  • 为什么使用模式匹配：提高代码的可读性和简洁性，减少错误，尤其是在处理复杂数据结构时。
  • 基础模式匹配：match表达式（可以用于模式匹配数字、字符串、枚举等）。

模式匹配的各种模式

  • 字面值模式
  • 变量模式
  • 通配符模式
  • 结构模式 （元组模式、枚举模式、解构模式类似的，展示如何结构元组、枚举和其他复杂的数据结构。）

守卫和绑定

  • 守卫：在模式匹配中，可以使用守卫来添加额外的条件判断。
  • 绑定：在模式匹配中，可以使用绑定来将模式中的值绑定到变量上。

模式匹配的应用场景

  • 处理错误
  • 解析命令行参数
  • 解析配置文件
  • 解析数据包
  • 解析xml或json等数据格式

ref和ref mut

使用场景

  • 借用数据而不转移所有权：在某些情况下，你只需要借用数据而不是转移其所有权。例如在递归数据结构中，借用数据可以避免所有权转移带来的复杂性。
  • 对数据进行修改：使用ref mut可以在模式匹配时对数据进行修改，而无需转移所有权。

错误处理

Rust中的错误主要分两类：

  • 可恢复错误，通常用于从系统全局角度来看可以接受的错误，例如处理用户的访问、操作等错误，这些错误只会影响某个用户自身的操作进程，而不会对系统的全局稳定性产生影响。
  • 不可恢复错误：刚好相反，该错误通常是全局性或者系统性错误，例如数组越界访问，系统启动时发生了影响启动流程的错误等等，这些错误的影响往往对于系统来说是致命的。
  • Result<T,E>用于可恢复错误
  • panic!用于不可恢复错误

被动触发

C语言中，尝试读取数据结构之后的值是未定义行为(undefined behavior)。你会得到任何对应数据结构中这个元素的内存位置的值，甚至是这些内存并不属于这个数据结构的情况。这被称为缓冲区溢出(buffer overread)，并可能会导致安全漏洞，比如攻击者可以像这样操作索引来读取储存在数据结构之后不被允许的数据。

主动调用

对此，Rust为我们提供了panic！宏，当调用执行宏时，程序会打印出一个错误信息，展开报错点往前的函数调用堆栈，最后退出程序。

panic时的两种终止方式

  • 栈展开(unwinding)(默认):Rust会回溯栈上数据和函数调用，因此也意味着更多的善后工作，好处是可以给出充分的报错信息和栈调用信息，便于事后的问题复盘
  • 直接终止(abort):不清理数据就直接退出程序，善后工作交与操作系统来负责
    对于绝大多数用户，使用默认选择是最好的，但是当你关心最终编译出的二进制可执行文件大小时，那么可以尝试去使用直接终止的方式，例如下面的配置修改 Cargo.toml 文件，实现在 release 模式下遇到 panic 直接终止:

传播错误

当函数的实现中调用了可能会失败的操作时，除了在这个函数中处理错误外，还可以选择让调用者知道这个错误并决定该如何处理。这被称为传播（propagating）错误，这样能更好的控制代码调用，因为比起你代码所拥有的上下文，调用者可能拥有更多信息或逻辑来决定应该如何处理错误。
